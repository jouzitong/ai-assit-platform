# 项目文档

`docs/` 用于保存 `ai-assit-platform` 的长期文档、接口契约、开发规范、运维手册、测试资料和阶段性方案。

## 文档入口

- [技术文档](./technical/README.md)
    - 记录当前真实架构、实现原理、前后端交互、配置参考和扩展边界。
- [开发规范](./dev-spec/README.md)
    - 记录开发过程中必须遵守的目录、分层、组件和编码约定。
- [接口文档](./api/)
    - 记录对外或跨模块接口契约、请求字段和协议行为。
- [运维手册](./operation-manual/)
    - 记录部署、配置操作、外部系统接入和故障处理方法。
- [测试资料](./test/)
    - 记录专项测试说明、测试数据、脚本和验收辅助材料。
- [设计与实施计划](./plans/)
    - 记录特定阶段的设计方案、实施计划、验收记录和历史决策。

## 分类原则

| 目录                  | 回答的问题              | 生命周期           |
|---------------------|--------------------|----------------|
| `technical/`        | 系统现在怎样实现、怎样交互、怎样扩展 | 随真实实现持续维护      |
| `dev-spec/`         | 开发时必须遵守什么          | 规范变更时维护        |
| `api/`              | 调用方怎样使用接口          | 契约变更时维护        |
| `operation-manual/` | 怎样部署、配置和排障         | 运维流程变更时维护      |
| `test/`             | 怎样验证能力             | 测试范围变更时维护      |
| `plans/`            | 为什么这样设计、准备怎样实施     | 保留历史，不要求持续追平实现 |

同一主题可以出现在多个目录，但职责不能重复。例如 Render JSON 的开发约束放在 `dev-spec`，运行机制和交互链路放在 `technical`
，聊天事件结构放在 `api`，阶段性演进方案放在 `plans`。
