# RAGFlow 知识库基础操作手册

> 适用版本：RAGFlow v0.26.4  
> 适用范围：通过 RAGFlow Web 控制台创建、配置、上传、解析和检索知识库（Dataset）。
> 文档入口：[RAGFlow 操作手册](README.md)。

## 1. 先理解几个概念

| 业务概念 | RAGFlow 概念 | 说明 |
|---|---|---|
| 知识库 / 大分类 | Dataset | 例如 FAQ、数据源说明、组件说明。 |
| 知识库中的文件 | Document | 上传的 Markdown、PDF、Word、Excel 等文件。 |
| 文档切片 | Chunk | RAGFlow 解析文档后用于检索的最小内容单元。 |
| 向量模型 | Embedding model | 将 Chunk 与用户问题转换为向量；创建知识库前必须可用。 |
| 检索测试 | Retrieval test | 用一个问题验证知识库是否召回了正确 Chunk。 |

一个知识库应只承载同一类、同一检索策略的内容。比如 FAQ、数据源口径、组件配置应拆成不同 Dataset，不建议混在一起。

## 2. 登录与前置检查

1. 在浏览器打开 RAGFlow 地址：`http://<服务器IP>:18080`。
2. 使用已创建的账号登录；首次使用可在登录页注册普通账号（若管理员未关闭注册）。
3. 打开模型配置页（通常在用户设置或 **Model providers / 模型供应商**）。
4. 确认至少存在一个可用的 Embedding 模型。

> RAGFlow v0.26.4 镜像不内置 Embedding 模型。知识库创建、文档解析和检索依赖 Embedding 模型服务；未配置时即使文件上传成功，也无法完成有效解析和检索。

配置模型时需要确认：

- 供应商、服务地址和 API Key 正确；
- 选择的是 **Embedding** 类型模型，而不是仅聊天模型；
- RAGFlow 服务可以访问模型地址；
- 记录模型标识，例如 `模型名@供应商`，创建 Dataset 时使用该模型。

可选：配置 Rerank 模型。它用于对初步召回结果二次排序，能提升复杂问题的准确度，但不是创建基础知识库的前置条件。

## 3. 创建第一个知识库

以下以“数据源与指标口径知识库”为例。

1. 进入左侧 **Knowledge base / 知识库**。
2. 点击 **Create knowledge base / 新建知识库**。
3. 填写基础信息：

   | 字段 | 推荐值 | 说明 |
   |---|---|---|
   | 名称 | `kb_datasource` | 使用稳定、易识别的英文或拼音标识；不要频繁修改。 |
   | 描述 | `数据源、表结构、字段解释和指标口径` | 写清内容范围，方便团队选择。 |
   | 权限 | 团队共享使用 `team` | 私人试验库可选个人权限。 |
   | Embedding 模型 | 已验证可用的模型 | 创建后不建议更换；更换应新建库并重新解析。 |

4. 选择解析/切片方式：常规文档选择 **Naive / 通用切片**。
5. 按下表填写基础解析参数。
6. 点击创建。

### 推荐的基础参数

| 参数 | FAQ | 数据源、指标、SQL 规则 | 组件与图表配置 |
|---|---:|---:|---:|
| 切片方式 | `qa` 或 `naive` | `naive` | `naive` |
| `chunk_token_num` | 512 | 768 | 1024 |
| 分隔符 | `\n!?;。；！？` | `\n\n\n` | `\n\n` |
| 版面识别 | DeepDOC | DeepDOC | DeepDOC |
| 自动关键词 | 3 | 5 | 5 |
| 自动问题 | 3 | 2 | 5 |
| 父子分块 | 关闭 | 建议开启 | 建议开启 |
| Excel 转 HTML | 关闭 | Excel 文件可开启 | 关闭 |

参数含义：

- `chunk_token_num`：单个 Chunk 的目标长度。过小会丢上下文，过大会导致召回不够精确。
- 分隔符：优先按标题、空行、自然段切分。结构化口径文档通常以连续空行分隔更稳妥。
- 父子分块：检索时命中细粒度子块，回答时可带回父块上下文；适合字段说明、组件 Schema 等结构化长文档。
- 自动关键词、自动问题：会增加解析成本，并可能需要可用的聊天模型；首次验证时可关闭，确认基础流程可用后再开启。

## 4. 上传并解析文档

1. 进入刚创建的 Dataset。
2. 点击 **Upload file / 上传文件**。
3. 选择一个小型、内容明确的文件先验证，例如 `指标口径.md`。
4. 文件上传完成后，选择该文档并点击 **Parse / 解析**。
5. 等待状态从“解析中”变为“完成”。
6. 打开文档详情或 **Chunks**，检查切片内容是否符合预期。

建议第一次只上传 1 至 3 个小文件。确认模型、解析方式和 Chunk 质量后，再批量导入历史资料。

### 不同文件类型的建议

| 文件类型 | 推荐切片方式 | 注意事项 |
|---|---|---|
| Markdown、TXT、普通 DOCX/PDF | `naive` | 用清晰标题和空行组织文档。 |
| FAQ、问答对 | `qa` 或 `naive` | 每条问答保持问题与答案完整相邻。 |
| Excel、CSV | `table` | 表头需清晰；数据源口径可按表或主题拆分。 |
| 长 PDF 手册 | `manual` 或 `book` | 先用少量页验证版面识别效果。 |
| PPT、演示稿 | `presentation` | 一页一个主题效果较好。 |
| 图片扫描件 | `picture` | 依赖 OCR/版面识别质量，建议人工抽查。 |

## 5. 检查切片质量

在 Chunk 列表中随机检查至少 5 个 Chunk，重点看：

- Chunk 是否在标题、表格行或一句话中间被不合理截断；
- 字段名、表名、指标定义与数值单位是否仍在同一上下文；
- PDF 是否出现乱码、页眉页脚反复混入正文；
- Excel 是否保留表头与行之间的对应关系；
- 自动生成的问题、关键词是否符合原文。

如果切片不理想，应先修改 Dataset 的解析参数，再对受影响文档执行重新解析。不要在已有大量 Chunk 后直接更换 Embedding 模型；正确做法是新建 Dataset、重新解析并切换业务侧的 Dataset ID。

## 6. 做一次检索验证

在知识库的检索测试页面输入一个答案明确的问题，例如：

```text
订单明细表的订单金额字段是什么含义？
```

检查：

1. 是否召回了正确文档；
2. 排名前几条是否包含字段名、定义、单位等关键上下文；
3. 召回内容是否来自当前 Dataset；
4. 没有答案时，是否明确返回无结果，而不是召回无关文本。

基础调优顺序建议：

1. 先修正文档结构和切片参数；
2. 再调整检索 `top_k`、相似度阈值和向量相似度权重；
3. 最后再启用或调整 Rerank。

## 7. 推荐的知识库拆分方式

| Dataset | 建议存放内容 | 是否与其他库混放 |
|---|---|---|
| `kb_faq` | 常见问题、标准问答、产品使用说明 | 不混放数据字典。 |
| `kb_datasource` | 表结构、字段解释、指标口径、数据源说明 | 不混放组件 JSON。 |
| `kb_components` | 组件 Schema、Render JSON、ECharts 配置 | 不混放业务制度文档。 |
| `kb_sql_rules` | SQL 生成规则、查询限制、示例 SQL | 可按数据域进一步拆分。 |

业务系统调用检索接口时，应只传与问题相关的 `dataset_ids`，而不是检索全部知识库。这样能降低无关召回并简化后续权限控制。

## 8. 常见问题

### 8.1 上传成功，但无法解析

优先检查：

- Dataset 是否选择了已配置、可访问的 Embedding 模型；
- 文档解析状态和 RAGFlow 后端日志；
- 文件格式、大小和内容是否正常；
- 是否误将自定义 ingestion pipeline 与内置 `chunk_method + parser_config` 同时配置。

### 8.2 解析完成，但检索不到结果

按顺序检查：

1. Chunk 数是否大于 0；
2. 测试问题是否与文档使用相同语言、术语；
3. Embedding 模型服务是否正常；
4. 相似度阈值是否过高、`top_k` 是否过小；
5. 是否选择了正确的 Dataset。

### 8.3 页面能登录，但创建知识库时提示模型错误

这通常表示账号已正常，但模型供应商尚未配置完成。先在模型配置页补齐 Embedding 模型的服务地址、密钥和模型标识，再重新创建或编辑 Dataset。

### 8.4 文档解析卡住

- 少量文档先验证，避免一次提交大量 PDF；
- 降低批处理量，例如将 `DOC_BULK_SIZE` 调整为 `1`；
- 查看 `/opt/ragflow/logs/backend.log`；
- 确认服务器内存和磁盘仍有余量。

## 9. 与业务系统对接

完成上述验证后，再将 Dataset ID 配置到业务平台。接口字段、批量上传和检索调用示例见：

- [RAGFlow 部署与 API 操作指南](ragflow_deploy_api_guide.md)

建议在业务侧维护如下映射：

```text
业务场景 -> RAGFlow 实例地址 -> Dataset ID -> 检索参数
```

这样未来新增 Dataset、迁移 Embedding 模型或拆分 RAGFlow 实例时，不需要修改业务调用逻辑。
