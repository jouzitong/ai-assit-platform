# AI 客户端与模型配置

## 1. 数据边界

- `ai_client_config` 是连接配置的唯一管理入口，保存客户端编码、类型、Base URL、凭据、启用状态和扩展参数。
- `ai_model_config` 保存平台模型编码、远端模型标识和启用状态，并通过 `client_id` 关联客户端。
- 新模型不得由页面手工录入远端模型标识；必须从所选客户端的标准模型列表接口获取后勾选。
- 旧模型记录允许 `client_id` 为空，运行时继续回退读取模型表中的历史连接字段，迁移完成前不得删除兼容字段。

## 2. 交互流程

模型管理页使用两步流程：

1. 新增或编辑客户端连接信息并保存。
2. 服务端使用保存后的凭据调用 Provider 标准模型接口，页面展示模型列表并提交勾选结果。

提交勾选结果时，同一客户端下勾选的模型启用，取消勾选的已有模型停用。页面不接收 API Key 回显，只展示掩码；编辑时 API Key 留空表示保留原值。

## 3. 服务分层

- `data-meta`：客户端和模型实体、CRUD、关联约束及批量启停持久化。
- `core-ai-engine`：按 `AiChatClientType` 路由 `AiChatService`，调用 `listModels` 获取远端模型。
- `providers/*`：实现具体 Provider 的标准模型接口适配；OpenAI 兼容客户端使用 `GET /v1/models`。
- `web`：暴露客户端管理、模型发现和模型保存接口，不直接实现 Provider 调用。

## 4. 运行时解析

- 对话运行时通过模型编码读取模型配置。
- 有 `client_id` 时，以客户端表中的类型、地址、凭据和启用状态为准。
- 客户端停用后，其关联模型即使自身为启用状态，也不得进入可用模型列表或执行对话。
- 客户端更新时允许同步兼容字段，但客户端表始终是新数据的配置源。
