# 弹窗与浮层组件规范

## 1. 基本原则

- 业务弹窗统一基于 Element Plus 实现，页面不得重复封装遮罩、焦点锁定、ESC 关闭和滚动锁定。
- 所有居中弹窗统一使用 `AppDialog`；表单、列表、详情等差异由页面通过内容插槽组合。
- 弹窗内容、表单校验和接口请求由业务页面负责，公共组件只管理布局、关闭行为和动作状态。
- 默认不允许点击遮罩关闭，避免误丢失未保存内容；确需开启时显式传入 `close-on-click-modal`。
- 浮层挂载使用响应式容器提供的目标节点，禁止新增无条件 `append-to-body` 的公共组件。

## 2. 组件与业务用法

| 类型 | 统一实现 | 适用场景 | 动作配置 |
| --- | --- | --- | --- |
| 居中弹窗 | `AppDialog` | 表单、列表、详情、预览和复合内容 | `confirm`、`close`、`none` |
| 确认便捷 API | `useAppConfirm` / `appConfirm` | 删除、覆盖、离开、不可逆操作 | 取消、确定 |
| 抽屉 | `AppDrawer` | 保留主页面上下文的筛选、配置和辅助任务 | 取消、确定 |

表单、列表、详情和确认属于业务用法，不定义平行的弹窗组件。全屏属于 `AppDialog` 的展示能力，也不单独定义组件。复杂分步流程可以在 `AppDialog` 中组合步骤组件，但不得重新实现弹窗壳。

`AppDialog` 通过 `action-mode="confirm | close | none"` 控制默认底部动作。业务页面通过默认插槽提供内容，不向公共组件传递 `form`、`list` 等业务类型。

## 3. 尺寸约定

- `small`：短确认信息、小型表单。
- `medium`：常规表单和详情，默认尺寸。
- `large`：数据表格、复杂表单和左右分栏。
- `extra-large`：大型预览和复杂工作区。
- 只有业务内容存在明确固定尺寸要求时才传入 `width`；常规页面使用尺寸枚举。
- `AppDialog` 的 `width` 与 `height` 支持百分比字符串；配置固定高度后，头部和底部操作区固定，只有内容区滚动。
- `AppDialog` 默认使用 `position="center"` 在当前浮层容器中水平、垂直居中；需要改变位置时使用九宫格位置值：`top-left`、`top`、`top-right`、`left`、`center`、`right`、`bottom-left`、`bottom`、`bottom-right`。
- 位置与容器边缘的距离默认使用公共间距 Token；业务确有需要时可通过 `offset` 传入 CSS 尺寸或数字像素值。尺寸仍优先使用 `size`，明确固定尺寸时使用 `width`、`height`。
- `AppDrawer` 只支持左右方向并始终占满容器高度，仅通过尺寸预设或 `width` 配置宽度。
- 小容器内由公共组件自动限制最大宽高，业务页面不重复编写视口计算样式。

## 4. 交互约定

- `v-model` 由父页面控制，弹窗关闭后页面负责清理或重置业务状态。
- 提交按钮通过 `confirming` 展示加载态，并在提交期间禁用取消操作。
- 表单校验失败时保持弹窗打开，并将焦点定位到第一个错误字段。
- 不可逆操作使用 `danger: true` 的确认弹窗，确认按钮文案应表达具体动作，例如“确认删除”。
- 关闭图标、取消按钮、ESC 和遮罩关闭最终都应走同一套业务清理逻辑。
- 长内容使用公共弹窗内容区滚动；页面不得在 `el-dialog__body` 上散落重复的 `max-height` 和 `overflow`。
- 确认、取消及其他底部操作始终位于弹窗底部，不随内容区域滚动。

## 5. 样式约定

- 宽度、内边距、圆角、阴影、遮罩和内容最大高度统一使用 `--app-dialog-*`、`--app-drawer-*` 与 `--app-overlay-mask` Token。
- 页面对弹窗内容使用业务类名，不覆盖 `.el-dialog`、`.el-drawer` 的结构样式。
- 底部操作统一使用 `LayoutDialogFooter`，主按钮位于右侧；破坏性操作使用 `danger` 语义。
- 需要自定义头部或底部时使用插槽，仍应保留公共间距和语义层级。
- 需要保留默认动作并追加按钮时使用 `footer-extra` 插槽；需要完全自定义按钮区时使用 `footer` 插槽。

## 6. 例外

- AI 助手悬浮窗、画布全屏预览等持续存在的工作区不是弹窗，可保留专用实现。
- 小型菜单、提示和轻量选择使用 `el-dropdown`、`el-popover`、`el-tooltip`，不要用 `AppDialog` 代替。
- 新增例外前先确认 Element Plus 是否已有对应组件，并在代码中说明不能使用统一组件的原因。

## 7. 测试入口

- 开发环境访问 `/test/dialog`，可测试统一 `AppDialog` 的表单、查看、列表、确认用法，以及额外按钮、尺寸、拖拽、全屏和遮罩关闭配置。
